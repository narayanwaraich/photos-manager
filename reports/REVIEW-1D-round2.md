## What is still open

**J1 (important, small): a walk that dies is treated as a walk that finished.** In `scan_root`, `let _ = walk_handle.await;` throws away the `JoinError`. If the walker thread ever panics, the writer sees the channel close, the scan looks complete, and the final transaction marks every row that was not reached as `missing`: exactly what decision (i) forbids. No production `unwrap`/`expect` exists today, so this needs a bug elsewhere, but it is the one remaining way to reach the wrong "missing", and the fix is small. Required: check the result; on `Err` return an error before the final transaction. Use a new `ScanError::WalkFailed` with code `scan_walk_failed`, a fixed message with no path, added to `ALL_CODES`, `errorCodes.ts`, the drift test and the leak test (the same pattern as the three existing scan codes); do not reuse `Database(PoolClosed)`. Test: a failure hook of the same kind as the existing ones (a `ScanOptions` field that makes the walker thread panic after the first batch), on a tree where one file was deleted after a first complete scan; assert that the scan returns `scan_walk_failed`, that no row is `missing`, and that the guard was released (a second scan starts). Show the test failing with the old `let _ =` restored, then passing.

**N1 (small): unused import on Windows.** `FolderStatus` in `scanner/tests.rs:11` is used only inside the Unix-only `chmod` test, so every Windows build prints `warning: unused import: FolderStatus` (it is in the laptop's `verify-1D.txt` and `scan-report-1D.txt`). `pnpm verify` does not lint test code, so nothing fails; move the import into that test.
