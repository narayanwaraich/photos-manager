## Findings

### Must fix: code and tests (the agent does these)

1. **Five repository functions have no test.** `list_volumes`, `list_roots`, `find_folder_by_key`, `find_file_by_key`, `count_for_root` are never called by any test. Task Part G asked for a test of each repository function. Add them (list returns what was inserted and in a stable order; `find_*_by_key` hits and misses; `count_for_root` after inserts and after a delete).
2. **Bad-value tests exist for only three of six enums.** `test_enum_check_sync_and_size_range` rejects an unlisted string for `VolumeKind`, `RootStatus` and `FolderStatus`, but not for `FileStatus`, `AssetKind` or `AssetStatus` (their loops only insert the listed variants). Add the three rejections (`CHECK constraint failed`), and one Rust-side test per enum that `FromStr` rejects an unlisted string.
3. **A property test that cannot fail.** `test_proptest_valid_components_never_contain_forbidden` (`filesystem/mod.rs:121`) draws names from `[a-zA-Z0-9_.-]`, which never contains `/`, `\`, NUL or `:`, and then asserts those characters are absent. The only way to fail is to produce `.` or `..` and the `if` filter removes them first. It tests nothing. Replace it with a property over arbitrary strings (including `/`, `\`, NUL, `:`, `.`, `..`, empty): `from_components` returns `Ok` **only if** the component is clean, and returns `Err` for every one that contains a forbidden character. Also add one property with non-ASCII input (for example `\PC{1,20}` or a hand-built alphabet with `e`, U+0301, `é`, `ß`, `İ`): building the same name in NFC and in NFD gives identical `path_key` bytes. Today the key property uses an ASCII alphabet, so NFC is covered by one example only. (Lesson 9: a test you have never seen fail may not test anything. The agent should show the new property failing against a deliberately broken validator, one line pasted in the report.)
4. **Collision detection reads the error message.** `files.rs:56` and `folders.rs:39` decide `PathKeyCollision` with `s.contains("UNIQUE constraint failed") && (s.contains("path_key") || s.contains("files.root_id"))`. That depends on SQLite's wording and on column order, and it silently maps any other unique failure to a different error. Use the typed check: `err.as_database_error().map(|e| e.kind()) == Some(sqlx::error::ErrorKind::UniqueViolation)`; then, on a unique violation, look the row up with `find_file_by_key` / `find_folder_by_key` inside the same connection: a row found means `PathKeyCollision` (carry the existing id), no row found means return `Database(err)` unchanged (it was the primary key). Add a test for the second branch (duplicate `id`, different key: must not be reported as a collision).
5. **`from_absolute` and `from_components` validate differently.** `from_components` calls `validate_component_str` (rejects empty, `.`, `..`, NUL, `/`, `\`, trailing `:`); `from_absolute` (`rel_path.rs:59` to `115`) re-implements only NUL and empty and never calls it. Result: a Unix file named `a\b.jpg` or `x:` is accepted by `from_absolute` and would be rejected if rebuilt with `from_components`, so a path the scanner stored may fail to round-trip later. Make `from_absolute` call the same validator for every component (the root's too), and add tests: both constructors reject the same table of names. This follows D26 as written (such names are skipped and reported); say in `docs/path-model.md` that on macOS a name containing a backslash or ending in a colon is legal on disk but is skipped and reported, so the owner is not surprised.
6. **The platform guard runs after the migrations, and stamps time 0.** `init_pool` (`database/mod.rs:82` to `86`) migrates first, then checks. A database stamped by the other OS is therefore migrated (written to) before it is refused, and a future migration could damage a file the app then refuses to open. Also `check_or_set_platform_guard(&mut conn, 0)` stores `updated_at_ms = 0`. Required: check before migrating when `app_settings` already exists (fresh files: migrate, then stamp); stamp with the real time in milliseconds (`SystemTime::now()` since the Unix epoch; a clock before 1970 is an error, not a panic); keep the function signature taking `now_ms` so tests can pass a fixed value. New test: a database that has only the 0A migration and a foreign stamp is refused **and** has no Phase 1 tables afterwards (`sqlite_master` has no `volumes`). Keep the existing mismatch test. Do not edit the two applied migration files.

### Must fix: report and docs

7. **"Deviations: none" is false.** The spec (v2.1.2) has `files.folder_id ... ON DELETE SET NULL`; the migration has `NOT NULL ... ON DELETE CASCADE`. The agent was right (with a mandatory root-folder row a `SET NULL` could never fire, and `NOT NULL` makes it contradict itself), and the task said every file has a non-NULL `folder_id`, but a changed delete rule is a deviation from the spec text and the task did not name the rule. I accept it as **D27(d)** (STATUS). The report must list it in §7 and explain the consequence: deleting a folder row deletes its files and their assets, so the scanner must mark folders `missing` and never delete them. Also mention in §7 the two commits that fixed Windows-only clippy lints (red run `43806156774`).

Say instead: "not reproduced; cause unknown; to be rechecked after `pnpm verify` runs on the laptop". The claim "`git status` stays clean after `pnpm verify`" is true for the Mac only; say so.
   - Acceptance table: items 1, 2 and 8 above are not "met" as written; fix the rows when the work is done.

9. **`docs/path-model.md` has factual errors and is over its length.**
   - Turkish i: it says capital `I` lowercases to "dotless `i` (U+0069)". U+0069 is the ordinary Latin `i`; the dotless letter is U+0131. Correct statement: Rust's `to_lowercase` maps `I` to `i` in every locale (Turkish rules would give dotless `ı`), and maps `İ` (U+0130) to `i` plus a combining dot (U+0307). A Turkish-named pair of files can therefore be given two different keys, or the same key where Turkish users would see two names; both cases are acceptable because the filesystem decides, and a clash is reported.
   - APFS: "filenames created via APFS/HFS+ often use decomposed NFD" is not right. HFS+ stores names decomposed; APFS keeps the bytes the creating program used and compares names without regard to normalization form. NFD names appear on macOS from older volumes, some archives, and some apps. Rewrite in those terms.
   - It calls `to_lowercase()` "standard Unicode case folding". It is lowercasing, not folding (for example `ß` stays `ß` where full folding gives `ss`), and NTFS and APFS each use their own case tables. Say the key is an approximation chosen to be conservative and that the volume decides in the end.
   - The task said one page at most; the file is 82 lines. Cut to about 60 lines (the three limits above in two or three sentences each).
   - Update the platform-guard section for item 6 (checked before migrating).
